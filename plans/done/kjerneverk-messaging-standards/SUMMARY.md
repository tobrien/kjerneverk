# Kjerneverk Messaging Standards - Summary

## Overview

Establish comprehensive messaging standards for Kjerneverk by creating foundational documentation that serves as the "bible" for all content generation, then systematically updating project READMEs and websites with consistent, vision-aligned messaging.

## Core Problem

Currently, Kjerneverk's messaging is inconsistent and doesn't capture the core philosophy:
- Main README describes it as "AI-assisted software development" (wrong framing)
- GitHub Pages uses "AI-assisted development workflows" (doesn't capture "structured formats" concept)
- No single source of truth for tone, voice, target audience, or core message
- Each time AI generates content, it lacks context about what Kjerneverk truly is

## Core Insight

**"The thing is bigger than just the thing"** - Prompts, Plans, and Documents are not just artifacts; they are constructs that encompass:
- **Process**: How you develop and evolve them
- **Lifecycle**: Multiple states, revisions, experimentation
- **Ways of thinking**: Metacognitive programming, ontology management
- **Infrastructure**: Tools, MCP servers, workflows that support them

## What Kjerneverk Really Is

Kjerneverk provides **structured formats for working with generative AI**. It moves away from:
- ❌ Freeform prompts
- ❌ Unstructured plans
- ❌ Documents generated without your input

Towards:
- ✅ **Control** over what you send to models
- ✅ **Ownership** of outputs (truly yours, not pattern-matched)
- ✅ **Constructs** with tools and infrastructure
- ✅ **Process** that makes thinking explicit

## Approach: Comprehensive Documentation Update

### Phase 1: Foundational Documents (kjerneverk.github.io)
Create the "bible" - documents that define messaging for all content generation:
1. **VISION.md** - Philosophical foundation
2. **CORE-MESSAGE.md** - Control, ownership, structured formats
3. **TONE-VOICE.md** - Pragmatic, opinionated, process-focused
4. **TARGET-AUDIENCE.md** - Technical users working with generative AI
5. **GLOSSARY.md** - Key terms and concepts

### Phase 2: Main Website (kjerneverk.github.io)
Update the landing page with:
1. Overview page with core concepts
2. Individual project pages (RiotPrompt, RiotPlan, RiotDoc)
3. Links to project documentation

### Phase 3: Project-Specific Updates
For each project (riotprompt, riotplan, riotdoc):
1. Update README.md with vision-aligned content
2. Update docs website (docs/ subdirectory)
3. Ensure consistency with foundational documents

## Success Criteria

- ✅ Single source of truth for Kjerneverk messaging
- ✅ Consistent messaging across all projects
- ✅ Clear, compelling explanation of what Kjerneverk is
- ✅ Visitors to any project understand the bigger vision
- ✅ AI tools can reference foundational docs for accurate content generation

## Key Principles

1. **Don't oversimplify** - Embrace complexity, use proper technical terms
2. **Emphasize process** - It's not just artifacts, it's how you work
3. **Control and ownership** - Making LLM outputs truly yours
4. **The thing is bigger than just the thing** - Core message throughout
