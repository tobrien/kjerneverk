User identified a critical UX problem with RiotPlan: During exploratory conversations about a plan, the model helps think through problems (which is good) but doesn't consistently capture insights back into the plan (which is bad). The challenge is establishing context so the model knows 'this conversation should be reflected in the plan' without breaking natural conversational flow. This is complicated because it sits at the intersection of Cursor's architecture (rules, MCP, context), model behavior (conversational vs structured), and user workflow (explicit vs implicit signals).
