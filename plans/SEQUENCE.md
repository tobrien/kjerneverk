## Plan Summaries

### Plan 01: Interactive Creation

**Problem**: `riotplan init` creates bare scaffolding but doesn't guide users through thoughtful plan creation.

**Solution**: 
- `riotplan create` with interactive prompts
- Analysis-first mode for complex plans
- Elaborate command for requirements refinement
- Amend command for plan feedback
- All prompts saved for recovery

**Key Commands**:
- `riotplan create <name>`
- `riotplan elaborate`
- `riotplan amend`
- `riotplan generate`

### Plan 02: Verification

**Problem**: Plans can drift from analysis requirements, and execution can be incomplete without anyone noticing.

**Solution**:
- Parse verification criteria from analysis
- Check plan step coverage of requirements
- Check execution completion against acceptance criteria
- Unified health score and recommendations

**Key Commands**:
- `riotplan verify`
- `riotplan verify --analysis`
- `riotplan verify --execution`
- `riotplan verify --criteria`

### Plan 03: RiotDoc (Future)

**Problem**: Document writing is non-linear, disjointed, and hard to reproduce.

**Solution**:
- Structured workspace for document creation
- Voice/tone configuration
- Evidence management
- Variable AI assistance levels
- Revision tracking

**Key Commands** (planned):
- `riotdoc create <name>`
- `riotdoc outline`
- `riotdoc draft`
- `riotdoc revise`
- `riotdoc export`

## Notes

- Each plan follows the RiotPlan format with prompt, SUMMARY, EXECUTION_PLAN, and step files
- Step files include Objective, Tasks, Acceptance Criteria, Testing, and Files Changed
- Plans are designed for human review before execution
- Updates to STATUS.md track progress through each plan
